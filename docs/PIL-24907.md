# PIL-24907 — Add todo statistics

Редакция 1. Статус: спецификация подготовлена для утверждения объёма; реализация не начата.

## Основания и цель

Добавить получение количества всех, открытых и выполненных дел из текущего списка.

Источники: [постановка задачи](/opt/hireminds/context/issue.md),
[правила проекта](../CLAUDE.md), [текущий API](../README.md#api),

[существующие тесты](../test/todos.test.ts), [команды и версии](../package.json).

## Границы объёма

После утверждения допустимы изменения только в `src/todos.ts`, `src/server.ts`,
`test/todos.test.ts`, `README.md` и этом документе `docs/PIL-24907.md`.
На фазе спецификации создаётся только этот документ.

В объём входят экспортируемая чистая функция `todoStats(list: TodoList)`,
маршрут `GET /todos/stats`, тесты и строка endpoint в таблице API README
с описанием ответа. Новые зависимости, изменения `.github`, инфраструктуры,
хранилища, UI, фильтрация статистики и дополнительные метрики исключены.
Существующие операции добавления, завершения и фильтрации дел сохраняют поведение.
Реализация и декомпозиция на задачи до утверждения не выполняются.

## Контракт и пользовательские сценарии

1. Потребитель модуля передаёт `TodoList` в `todoStats` и получает новый объект
   ровно с полями `{ total, open, done }`, значения — неотрицательные целые числа.
   `total` равно `list.items.length`, `done` — числу элементов с `done === true`,
   `open` — числу элементов с `done === false`; `total === open + done`.
2. Клиент вызывает `GET /todos/stats` и получает HTTP 200 с JSON того же формата
   и существующим `Content-Type: application/json; charset=utf-8`.
   Подсчёт охватывает весь текущий список в памяти процесса. Параметры query,
   включая `filter`, не меняют результат; тело запроса не требуется.
3. После добавления дела счётчики `total` и `open` увеличиваются на один.
   После завершения открытого дела `open` уменьшается на один, `done` увеличивается
   на один, `total` сохраняется. Повторное завершение не меняет статистику.

## Критерии приёмки

| Состояние списка | Точный результат |
| --- | --- |
| Пустой список | `{ total: 0, open: 0, done: 0 }` |
| Три дела, одно завершено | `{ total: 3, open: 2, done: 1 }` |
| Два завершённых дела | `{ total: 2, open: 0, done: 2 }` |
| Два открытых дела | `{ total: 2, open: 2, done: 0 }` |

- Функция не изменяет `nextId`, массив `items`, его порядок и поля объектов дел;
  ссылки на массив и объекты дел остаются прежними. Результат не содержит
  дополнительных полей, содержимого дел или `nextId`.
- HTTP endpoint отражает текущее состояние и сам не меняет список.
- README содержит метод, путь и поля ответа нового endpoint.

## Исключения и зависимости

Функция принимает корректный `TodoList` по существующему TypeScript-контракту;
валидация произвольных входных значений не входит в объём. Идентификаторы,
заголовки и `nextId` не влияют на подсчёт. Ошибки других маршрутов и ответ 404
для неподдерживаемых путей/методов сохраняются. После перезапуска статистика
равна нулям, как следствие существующего хранения в памяти.

Используются существующие Node.js >=20, TypeScript, Vitest и HTTP-обработчик.
Внешние сервисы, миграции и новые пакеты не требуются.
