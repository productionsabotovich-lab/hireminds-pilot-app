# PIL-24908 — Add todo statistics

Редакция 1. Статус: подготовлена к утверждению объёма. Реализация начинается после утверждения.

## Основание и цель

Постановка: [PIL-24908](/opt/hireminds/context/issue.md). Ограничения: [правила проекта](../CLAUDE.md), [документы задач](README.md), [текущий API](../README.md).

Клиент получает количество всех, открытых и выполненных дел текущего списка одним запросом.

## Контракт и сценарии

В [src/todos.ts](../src/todos.ts) экспортируется чистая функция `todoStats(list: TodoList)`, возвращающая объект ровно с тремя числовыми полями `{ total, open, done }` без дополнительных полей. `total` — число элементов `list.items`, `done` — число элементов с `done === true`, `open` — число элементов с `done === false`. Для корректного `TodoList` всегда `total = open + done`. Поле `nextId` не участвует в подсчёте.

В [src/server.ts](../src/server.ts) `GET /todos/stats` возвращает HTTP 200, `Content-Type: application/json; charset=utf-8` и результат `todoStats` для текущего состояния процесса. Подсчёт охватывает весь список; параметры запроса, включая `filter`, его не ограничивают. Запрос не меняет состояние.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Список пуст, включая запуск нового процесса | `{ "total": 0, "open": 0, "done": 0 }` |
| Созданы три дела, одно выполнено | `{ "total": 3, "open": 2, "done": 1 }` |
| Все три дела выполнены | `{ "total": 3, "open": 0, "done": 3 }` |
| После получения статистики добавлено дело | Следующий запрос увеличивает `total` и `open` на 1 |
| Открытое дело выполнено | Следующий запрос уменьшает `open` и увеличивает `done` на 1, сохраняя `total` |

## Критерии приёмки

1. Функция и маршрут соблюдают указанный контракт и сценарии; все значения — неотрицательные целые числа, набор ключей точный.
2. Функция не изменяет `list`, `nextId`, массив `items`, его порядок, ссылки на элементы или поля элементов; работает и с замороженным корректным входом. Повторный вызов для неизменённого списка даёт те же значения.
3. В [test/todos.test.ts](../test/todos.test.ts) добавлены автоматические проверки пустого списка, смешанного списка, всех выполненных дел и отсутствия мутации входа.
4. Существующие операции создания, выполнения и фильтрации дел сохраняют поведение. Статистика отражает актуальное состояние после этих операций.
5. В [README.md](../README.md) описан `GET /todos/stats` и формат ответа с примером.
6. `npm run check` и `npm test` проходят после реализации.

## Границы объёма и исключения

Разрешены изменения только пяти файлов: `src/todos.ts`, `src/server.ts`, `test/todos.test.ts`, `README.md` и этой спецификации `docs/PIL-24908.md`. На фазе спецификации создаётся только этот документ, без реализации и декомпозиции на задачи.

Новые зависимости, изменения `.github`, инфраструктуры и прочих файлов исключены. Не входят UI, проценты, группировки, фильтрация статистики, хранение на диске, авторизация и новые операции над делами. Состояние остаётся в памяти процесса и сбрасывается при перезапуске.

Функция принимает корректный `TodoList`; дополнительная валидация произвольного входа не требуется. Для иных HTTP-методов и несовпадающих путей сохраняется существующий ответ 404; новые варианты обработки ошибок не вводятся.

## Зависимости и ограничения процесса

Используются существующие [типы и чистые функции](../src/todos.ts), [HTTP-обработчик](../src/server.ts) и [Node.js >=20, TypeScript, Vitest](../package.json). Внешних сервисов не требуется. I/O остаётся в сервере, логика подсчёта — в модуле списка.

Реализация зависит от утверждения этой редакции платформой. Последующая работа ведётся в ветке `hm/PIL-24908-<slug>` по [правилам постановки](/opt/hireminds/context/issue.md); документ включается в единственный PR реализации. Аналитик PR не открывает.
