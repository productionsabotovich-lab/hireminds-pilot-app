## Сценарии и контракт

1. Клиент запрашивает `GET /todos/stats` и получает HTTP 200 с JSON-объектом
   ровно `{ "total": number, "open": number, "done": number }` и существующим
   заголовком `Content-Type: application/json; charset=utf-8`.
2. Для пустого списка ответ равен `{ "total": 0, "open": 0, "done": 0 }`.
3. После добавления дела увеличиваются `total` и `open`; после выполнения
   существующего дела увеличивается `done`, уменьшается `open`, `total` сохраняется.
   Повторное выполнение того же дела не меняет статистику.
4. Чтение статистики не меняет список; повторный запрос без изменений данных
   возвращает те же значения.

В `src/todos.ts` экспортируется синхронная чистая функция `todoStats(list: TodoList)`,
возвращающая объект ровно с полями `total`, `open`, `done`:

- `total` — количество элементов `list.items`;
- `open` — количество элементов с `done === false`;
- `done` — количество элементов с `done === true`.

Все значения — неотрицательные целые числа, `total === open + done`.
Функция не изменяет `list`, `nextId`, массив `items`, порядок и поля его элементов.
HTTP-обработчик использует эту функцию для текущего состояния процесса.

## Исключения и совместимость

Вход функции соответствует существующему типу `TodoList`; проверка произвольных
некорректных объектов не добавляется. Статистика охватывает весь текущий список;
query-параметры, включая `filter`, игнорируются по принятому поведению обработчика
для неприменимых параметров. Другие методы для `/todos/stats` получают существующий
ответ 404 `{ "error": "not found" }`. Состояние по-прежнему хранится в памяти
и сбрасывается при перезапуске. Контракты списка, добавления и выполнения сохраняются.

## Критерии приёмки

- `todoStats(emptyList())` возвращает ровно `{ total: 0, open: 0, done: 0 }`.
- Для трёх дел, из которых два открыты и одно выполнено, результат ровно
  `{ total: 3, open: 2, done: 1 }`.
- Для двух выполненных дел результат ровно `{ total: 2, open: 0, done: 2 }`.
- Отдельный тест подтверждает отсутствие мутации списка и его элементов,
  включая `nextId`, значения полей и порядок элементов.
- `GET /todos/stats` соответствует HTTP-контракту для пустого и изменённого
  состояния; запрос статистики не изменяет последующий результат `GET /todos`.
- README содержит новый endpoint и назначение его полей.
- Изменения укладываются в перечень файлов и ограничения объёма выше;
  существующие тесты и проверка типов проходят.

## Зависимости и план проверки

Используются существующие `TodoList`, состояние HTTP-сервера, Node.js >=20,
TypeScript и Vitest из [package.json](../package.json). Внешних сервисов и новых
пакетов не требуется. Начало реализации зависит от утверждения этой редакции
спецификации платформой.

После утверждения: в `test/todos.test.ts` проверить четыре обязательных случая
функции (пустой, смешанный, полностью выполненный список и отсутствие мутации).
HTTP-контракт проверить через существующий обработчик или локальный сервер:
пустое состояние, добавление и выполнение дел, повторное выполнение, повторное
чтение, игнорирование `filter`, ответ 404 для неподдерживаемого метода.
Не создавать отдельный тестовый файл. Выполнить `npm run check` и `npm test`;
проверить diff на соблюдение разрешённого набора файлов и наличие endpoint в README.
Это план будущей проверки реализации, а не заявление о выполненных проверках.
