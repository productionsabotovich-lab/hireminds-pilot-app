# PIL-24912 — Add todo statistics

## Цель и основания

Пользователь получает количество всех, открытых и выполненных дел текущего списка одним запросом.

## Контракт

`todoStats(list: TodoList)` возвращает объект ровно с тремя числовыми полями `{ total, open, done }`:

- `total` — число элементов `list.items`.
- `done` — число элементов с `done === true`.
- `open` — число элементов с `done === false`.

Для допустимого `TodoList` значения — неотрицательные целые числа; `total === open + done`. `nextId`, значения идентификаторов и заголовки на подсчёт не влияют. Функция не изменяет список, массив `items` или его элементы и не выполняет I/O.

`GET /todos/stats` возвращает `200 OK`, `Content-Type: application/json; charset=utf-8` и JSON с теми же тремя полями для текущего состояния процесса. Запрос не меняет состояние. Параметры запроса, включая `filter`, не изменяют результат: статистика относится ко всему списку. Другие методы на этом пути используют существующий ответ `404 { "error": "not found" }`. Новая валидация некорректных объектов вне типа `TodoList` не требуется.

## Пользовательские сценарии и критерии приёмки

| Сценарий | Действие | Ожидаемый результат |
| --- | --- | --- |
| Пустой список | Вызвать функцию или запросить статистику нового процесса | Ровно `{ "total": 0, "open": 0, "done": 0 }` |
| Только открытые дела | Создать два дела и запросить статистику | Ровно `{ "total": 2, "open": 2, "done": 0 }` |
| Смешанный список | Создать три дела, завершить одно, запросить статистику | Ровно `{ "total": 3, "open": 2, "done": 1 }` |
| Все дела выполнены | Завершить все три дела и запросить статистику | Ровно `{ "total": 3, "open": 0, "done": 3 }` |
| Повторный подсчёт | Повторить вызов без изменения списка | Тот же результат; список, `nextId`, массив и все поля элементов не изменились |
| Последующие изменения | После запроса добавить или завершить дело и снова запросить статистику | Новый ответ отражает актуальное состояние; сам запрос статистики его не меняет |

Дополнительные критерии: README содержит новый метод и путь с кратким описанием результата; прежние операции добавления, завершения и фильтрации продолжают работать; соблюдён перечень разрешённых файлов.

## Исключения и зависимости

Пустой список — штатный случай. Данные живут в памяти процесса, поэтому после перезапуска статистика снова нулевая. Некорректные идентификаторы и ошибки существующих операций обрабатываются по действующему контракту; новых ошибок статистики для допустимого списка нет.

Используются существующие типы `TodoList`/`Todo`, состояние HTTP-сервера, Node.js >=20 и установленный инструментарий TypeScript/Vitest из [package.json](../package.json). Внешние сервисы и новые пакеты не нужны.

## План проверки после утверждения

1. В `test/todos.test.ts` проверить точное равенство результата для пустого, смешанного и полностью выполненного списка; проверить также случай только открытых дел.
2. Отдельно проверить отсутствие мутации: сохранить снимок входного списка со всеми полями и ссылки на `items` и элементы, вызвать подсчёт повторно и сравнить данные и ссылки. Замораживание списка, массива и элементов допустимо как дополнительная проверка.
3. Проверить HTTP на новом процессе: нулевая статистика, добавление трёх дел, завершение одного, затем всех; сверить статус, JSON и Content-Type. Сравнить `GET /todos` до и после запроса статистики. Проверить игнорирование `filter` и существующий ответ для неподдерживаемого метода. Проверки допустимо выполнить вручную, без дополнительных файлов.
4. Выполнить `npm run check` и `npm test`; проверить README и дифф на соблюдение границ объёма. Результаты фиксировать после реализации.
