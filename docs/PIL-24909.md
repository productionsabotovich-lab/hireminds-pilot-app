# PIL-24909 — Add todo statistics

Редакция 1. Статус: подготовлена к утверждению объёма; реализация не начата.

## Цель и основания

Пользователь получает количество всех, открытых и выполненных дел текущего списка одним запросом.

Источники требований и ограничений: [issue PIL-24909](/opt/hireminds/context/issue.md), [правила проекта](../CLAUDE.md), [API и хранение состояния](../README.md), [правила документов](README.md). Текущие контракты: [TodoList и чистые функции](../src/todos.ts), [HTTP-обработчик](../src/server.ts), [тесты](../test/todos.test.ts), [команды и зависимости](../package.json).

## Контракт и пользовательские сценарии

- Экспортировать из `src/todos.ts` функцию `todoStats(list: TodoList)`, возвращающую объект ровно с тремя числовыми полями `{ total, open, done }`.
- `total` равен длине `list.items`; `done` — числу элементов с `done === true`; `open` — числу элементов с `done === false`. Для корректного `TodoList`: `total = open + done`. `nextId` на результат не влияет.
- Функция не изменяет список, `nextId`, массив элементов, порядок или свойства элементов; не выполняет I/O.
- `GET /todos/stats` возвращает HTTP 200 и JSON с тем же объектом для текущего состояния сервера, с существующим заголовком `application/json; charset=utf-8`. Запрос не меняет состояние.
- Статистика относится ко всему текущему списку. Query-параметры, включая `filter`, не ограничивают подсчёт, как и прочие неиспользуемые параметры существующего API.
- После добавления дела растут `total` и `open`; после завершения открытого дела `open` уменьшается, `done` растёт, `total` сохраняется. Повторное завершение выполненного дела не изменяет статистику.
- При пустом списке пользователь получает `{ "total": 0, "open": 0, "done": 0 }`. При перезапуске процесса статистика снова отражает пустое состояние согласно существующей модели хранения.

## Критерии приёмки

1. Пустой список даёт ровно `{ total: 0, open: 0, done: 0 }`.
2. Список из двух открытых и одного выполненного дела даёт ровно `{ total: 3, open: 2, done: 1 }`.
3. Список из двух выполненных дел даёт ровно `{ total: 2, open: 0, done: 2 }`.
4. Входной список, массив и элементы после вызова сохраняют значения и ссылки; вызов на глубоко замороженном корректном списке успешен. Повторный вызов даёт тот же результат.
5. HTTP-запрос к `/todos/stats` возвращает 200, JSON content-type и ровно три поля с актуальными значениями; последовательность «пустой список → добавить два дела → завершить одно» даёт соответственно `0/0/0`, `2/2/0`, `2/1/1` (total/open/done). Повторный GET не меняет состояние; `?filter=done` не меняет результат.
6. Существующие операции списка и обработка неизвестных маршрутов сохраняют поведение. README содержит новый эндпоинт и описание возвращаемых счётчиков.
7. Нет новых зависимостей, изменений `.github` или инфраструктуры. Изменения ограничены перечисленными ниже файлами. `npm run check` и `npm test` проходят.

## Границы объёма и исключения

Единственный новый файл — `docs/PIL-24909.md`. После утверждения допустимы изменения только четырёх существующих файлов: `src/todos.ts`, `src/server.ts`, `test/todos.test.ts`, `README.md`.

В объём входят чистый подсчёт, один GET-маршрут, проверки нового поведения в существующем тестовом файле и документация API. Другие методы для `/todos/stats` остаются в существующей обработке неизвестных маршрутов (404).

Вне объёма: UI, хранение на диске, статистика по фильтрам или пользователям, проценты, даты, новые поля Todo, новые зависимости, рефакторинг архитектуры и инфраструктуры. Валидация некорректных объектов вне типа `TodoList` не добавляется. Эта редакция не является разрешением на реализацию и не содержит декомпозиции работ.

## Зависимости и план проверки

Используются существующие `TodoList`, состояние HTTP-сервера, Node.js >=20, TypeScript и Vitest из [package.json](../package.json). Новых внешних сервисов и продуктовых зависимостей нет.

После утверждения: автоматические тесты в `test/todos.test.ts` проверяют пустой, смешанный, полностью выполненный списки и отсутствие мутаций. Проверка мутаций включает сохранение значений и ссылок и глубоко замороженный вход. HTTP-проверка через существующий `handle` и временный сервер на свободном порту проверяет сценарий критерия 5, формат ответа и сохранение прежних маршрутов; сервер закрывается по завершении. Новые тестовые файлы не создаются. Выполняются `npm run check` и `npm test`; README и список изменённых файлов сверяются с этой спецификацией.

На фазе спецификации проверки реализации не выполняются. PR и CI относятся к следующей фазе согласно [issue](/opt/hireminds/context/issue.md).
