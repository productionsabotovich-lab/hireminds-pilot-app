## Цель и границы

Клиент получает количество всех, открытых и выполненных дел текущего списка одним запросом.

В объём реализации входят только `src/todos.ts`, `src/server.ts`, `test/todos.test.ts` и `README.md`: экспорт `todoStats`, маршрут статистики, тесты и описание эндпоинта. Этот документ фиксирует объём и не является реализацией. Изменения зависимостей, `.github`, инфраструктуры, хранения данных, существующих API и пользовательского интерфейса исключены. Разбиение на задачи и реализация начинаются после утверждения спецификации платформой.

## Контракт

`todoStats(list: TodoList): { total: number; open: number; done: number }` — чистая синхронная функция в `src/todos.ts`.

- Возвращает объект ровно с тремя ключами `total`, `open`, `done`.
- `total` равен длине `list.items`; `done` — числу элементов с `done === true`; `open` — числу элементов с `done === false`.
- Все значения — неотрицательные целые; `total === open + done` для корректного `TodoList`.
- Не изменяет список, `nextId`, массив `items`, порядок элементов или поля самих элементов. Не выполняет I/O.
- Для пустого списка результат `{ total: 0, open: 0, done: 0 }`.
- Принимает существующий тип `TodoList`; валидация некорректных объектов вне TypeScript-контракта не добавляется.

`GET /todos/stats` возвращает HTTP 200, `Content-Type: application/json; charset=utf-8` и JSON с указанными тремя полями, вычисленными по текущему состоянию сервера. Запрос не изменяет состояние. Как и существующие маршруты, использует pathname: параметры запроса не меняют статистику; `filter` не ограничивает подсчёт. Остальные методы на этом пути сохраняют существующий ответ 404. Данные по-прежнему хранятся в памяти процесса.

## Пользовательские сценарии и критерии приёмки

1. До добавления дел клиент запрашивает статистику и получает `{ total: 0, open: 0, done: 0 }`.
2. В списке из трёх дел два открыты, одно выполнено: функция и эндпоинт возвращают `{ total: 3, open: 2, done: 1 }`.
3. Все три дела выполнены: результат `{ total: 3, open: 0, done: 3 }`.
4. После добавления дела `total` и `open` увеличиваются на один. После завершения открытого дела `open` уменьшается на один, `done` увеличивается на один, `total` сохраняется. Повторное завершение уже выполненного дела не меняет статистику.
5. Вызов функции сохраняет исходные значения и ссылки списка, массива и элементов. Повторные GET-запросы статистики не меняют список дел.
6. Существующие добавление, завершение и фильтрация дел сохраняют поведение; README описывает новый метод, путь и форму ответа.

## Исключения и зависимости

Нет процентов, группировок, фильтрации статистики, истории, новых полей Todo, новых кодов ошибок, авторизации или постоянного хранения. Не вводятся дополнительные зависимости. Используются существующие Node.js >=20, TypeScript, node:http и vitest: [конфигурация](../package.json). Новые требования к развёртыванию отсутствуют.

- В `test/todos.test.ts` добавить проверки пустого, смешанного и полностью выполненного списка с точным сравнением объекта, включая отсутствие лишних ключей.
- Проверить отсутствие мутаций: сравнить полный снимок списка до и после вызова; проверить сохранность ссылок и порядка. Замороженный вход допустим как дополнительный способ обнаружения записи.
- Проверить HTTP на изолированном процессе: пустая статистика; добавление трёх дел; завершение одного, затем остальных; повторное завершение; повторный GET и запрос с `filter=open`. Сверять статус, Content-Type, точный JSON и сохранность списка через GET /todos. Проверить 404 для POST /todos/stats.
- Выполнить обязательные `npm run check` и `npm test`, сохранив существующие тесты. Проверить описание эндпоинта в README и отсутствие изменений за пределами разрешённого объёма.
