## Цель и сценарии

Клиент получает количество всех, открытых и завершённых дел текущего списка одним запросом `GET /todos/stats`. На пустом состоянии он получает нулевые значения; после добавления и завершения дел — актуальные счётчики. Запрос статистики не меняет список и доступен повторно без побочных эффектов.

## Контракт

В `src/todos.ts` экспортируется чистая функция `todoStats(list: TodoList)`, возвращающая объект ровно с тремя числовыми полями `{ total, open, done }`:

- `total` — число элементов `list.items`;
- `done` — число элементов с `done === true`;
- `open` — число элементов с `done === false`.

Для корректного `TodoList` значения — неотрицательные целые числа, `total === open + done`. При подсчёте не используются `nextId`, идентификаторы или заголовки. Входной объект, массив, порядок элементов и все поля элементов остаются неизменными.

В `src/server.ts` запрос `GET /todos/stats` возвращает HTTP 200, существующий JSON content type и тело указанной формы для текущего состояния процесса. Пример: `{"total":3,"open":2,"done":1}`. Параметры запроса не фильтруют статистику: считаются все дела. Действующие маршруты сохраняют поведение; неподдерживаемые методы следуют существующему поведению маршрутизатора (404).

## Критерии приёмки

1. Экспорт `todoStats` доступен из `src/todos.ts` и возвращает ровно поля `total`, `open`, `done`.
2. Пустой список возвращает `{ total: 0, open: 0, done: 0 }`.
3. Список из двух открытых и одного завершённого дела возвращает `{ total: 3, open: 2, done: 1 }`.
4. Список из двух завершённых дел возвращает `{ total: 2, open: 0, done: 2 }`.
5. Вызов сохраняет весь входной список и элементы, включая ссылки, порядок, `nextId`, идентификаторы, заголовки и флаги `done`.
6. `GET /todos/stats` возвращает 200 и JSON указанной формы, отражающий состояние после существующих операций добавления и завершения. Повторный запрос не меняет состояние.
7. Четыре обязательных сценария (пустой, смешанный, полностью завершённый список и отсутствие мутаций) покрыты автоматическими тестами в `test/todos.test.ts`.
8. README документирует эндпоинт; проверки `npm run check` и `npm test` проходят; изменения реализации соответствуют границам объёма.

## Исключения и пограничные случаи

Пустой список — штатный случай. Полностью открытый список имеет `done: 0`. Повторное завершение дела не увеличивает счётчик сверх числа завершённых элементов. Пропуски в идентификаторах не влияют на результат. Статистика сбрасывается вместе с существующим состоянием при перезапуске сервера. Валидация некорректных объектов за пределами типа `TodoList` не добавляется.

## План проверки после утверждения

Автоматически проверить четыре обязательных сценария точным сравнением результата, включая отсутствие лишних полей. Для проверки мутаций сохранить снимок значений и ссылки списка, массива и элементов и сравнить их после вызова; допустимо дополнительно заморозить вход.

Выполнить `npm run check` и `npm test`. На свежем процессе сервера проверить HTTP 200 и JSON для пустого состояния, затем добавить два дела и завершить одно: ожидается `{ total: 2, open: 1, done: 1 }`. Повторить запрос статистики и сверить список через `GET /todos`; проверить действующие маршруты и независимость статистики от `filter`. Просмотреть diff на соответствие разрешённым файлам и ограничениям.
