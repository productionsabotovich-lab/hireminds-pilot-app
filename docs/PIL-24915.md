## Контракт

В `src/todos.ts` экспортируется чистая функция `todoStats(list: TodoList)`, возвращающая объект ровно с полями `{ total: number, open: number, done: number }`:

- `total` — число элементов `list.items`;
- `done` — число элементов с `done === true`;
- `open` — число элементов с `done === false`;
- для корректного `TodoList` все значения — неотрицательные целые числа, `total = open + done`.

Функция не изменяет объект `list`, `nextId`, массив `items`, порядок и ссылки его элементов, а также поля каждого элемента. Повторный вызов с тем же состоянием даёт те же значения. Вход соответствует существующему типу `TodoList`; новая проверка некорректных структур и новые ошибки не требуются.

`GET /todos/stats` возвращает HTTP 200, `Content-Type: application/json; charset=utf-8` и JSON с теми же тремя полями, вычисленный из текущего состояния сервера через `todoStats`. Запрос ничего не меняет. Подсчёт выполняется по всему списку; параметры query, включая `filter`, на него не влияют, как и прочие неподдерживаемые параметры существующих маршрутов. Новые методы для этого пути не добавляются; неподдерживаемый метод получает существующий ответ 404 `{ "error": "not found" }`.

README дополняется строкой API для `GET /todos/stats` с описанием полей ответа. Статистика использует существующее состояние в памяти; после перезапуска оно пустое.

## Пользовательские сценарии и критерии приёмки

1. Клиент запрашивает статистику пустого списка: функция и HTTP возвращают ровно `{ "total": 0, "open": 0, "done": 0 }`.
2. Клиент создаёт три дела и завершает одно: статистика равна `{ "total": 3, "open": 2, "done": 1 }`.
3. Все три дела завершены: статистика равна `{ "total": 3, "open": 0, "done": 3 }`.
4. Все три дела открыты: статистика равна `{ "total": 3, "open": 3, "done": 0 }`.
5. Повторное завершение уже выполненного дела не увеличивает `done`; учитываются элементы, а не число операций завершения.
6. После вызова функции исходный список, `nextId`, массив и каждый элемент сохраняют значения и ссылки. Запрос статистики не меняет последующие ответы списка и статистики.
7. HTTP-ответ содержит только `total`, `open`, `done`, отражает актуальные добавления и завершения и не зависит от `filter`.
8. Существующие добавление, завершение и фильтрация продолжают работать; README описывает новый маршрут; нет изменений за пределами разрешённых пяти файлов.

## Исключения и зависимости

Пустой список — штатное состояние с нулевыми счётчиками. Отсутствие выполненных или открытых дел не является ошибкой. В статистике нет поиска по id или чтения тела запроса; отдельные ошибки этих операций не вводятся. Существующие ответы ошибок других маршрутов сохраняются.

Зависимости: существующие `TodoList` и `Todo.done`, состояние и JSON-ответ в HTTP-обработчике, Node.js >=20, TypeScript и Vitest из текущего [package.json](../package.json). Внешние сервисы и новые пакеты не нужны.
